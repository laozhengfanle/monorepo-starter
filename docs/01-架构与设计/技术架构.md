# 技术架构

> 分层架构、请求生命周期、GraphQL vs REST 决策。读完后应能回答"一个请求进来后发生了什么"。

## 1. 分层架构

```text
┌─────────────────────────────────────────────────────────────┐
│ apps/admin（React 19 + Vite 8 + antd 6 + TanStack Query）     │
│   features/（业务页）→ shared/（应用内共享）→ @starter/api-client │
└──────────────────────────┬──────────────────────────────────┘
                           │ REST(/api/*, 经 orval client) + GraphQL(/graphql) + WS(/socket.io)
┌──────────────────────────▼──────────────────────────────────┐
│ apps/server（NestJS 11 + Express，端口 3301）                  │
│                                                             │
│   modules/（业务域：auth/admin-account/... 每域一模块）          │
│        │ 依赖
│   common/（横切基建：cache/graphql/logger/metrics/notifications/│
│           prisma/storage/tasks/throttler/dataloader）          │
│        │ 依赖
│   @starter/server-core（BizException/异常过滤器/Swagger）        │
│   @starter/contracts（zod 契约：输入校验/类型）                  │
└──────────────────────────┬──────────────────────────────────┘
                           │ Prisma 7（driver adapter: @prisma/adapter-pg）
┌──────────────────────────▼──────────────────────────────────┐
│ PostgreSQL                                                 │
└─────────────────────────────────────────────────────────────┘
```

**依赖方向（自上而下，禁止反向）**：

1. `apps/*`（应用层）→ `packages/shared/*`（共享层）
2. server 内部：`modules/` → `common/` → `@starter/server-core` / `@starter/contracts`
3. `common/` 不依赖任何 `modules/`（否则循环依赖）

模块边界由 `pnpm lint:boundaries`（ESLint `@nx/enforce-module-boundaries`）机器强制，tag 规则见《目录结构.md》。

## 2. server 内部职责划分

| 目录         | 职责                                  | 是否可依赖业务 |
| ------------ | ------------------------------------- | -------------- |
| `app/`       | 根模块、应用装配（createApp）         | 是             |
| `modules/`   | 业务域：认证、账户、角色、菜单、字典… | —              |
| `common/`    | 横切基建，与业务无关                  | 否             |
| `config/`    | 环境变量 zod 校验（`validateEnv`）    | 否             |
| `health/`    | Terminus 健康检查（`/health`）        | 否             |
| `generated/` | prisma client 生成物                  | 否             |

应用装配在 `app-setup.ts` 的 `createApp()` 完成（测试可直接 import，不监听端口）：

```ts
// apps/server/src/app-setup.ts（节选）
export async function createApp(): Promise<INestApplication> {
  const app = await NestFactory.create(AppModule, { bufferLogs: true });
  app.useLogger(app.get(Logger)); // pino 结构化日志
  app.use(helmet()); // 安全头
  app.use(compression()); // 响应压缩
  app.use(cookieParser());
  app.use('/uploads', express.static(UPLOAD_DIR)); // 上传文件静态访问
  app.useGlobalPipes(new ZodValidationPipe()); // zod 全局校验管道
  app.useGlobalFilters(new AllExceptionsFilter()); // 失败统一 envelope
  app.enableCors({ origin: corsOriginsFromEnv() }); // CORS_ORIGINS 白名单
  configureSwagger(app); // /api-docs
  await app.init();
  return app;
}
```

## 3. 请求生命周期

### 3.1 REST 请求（如 `POST /api/auth/login`）

```text
浏览器 → Vite 代理(/api 剥离前缀) → Express(NestJS)
  → helmet/compression/cookieParser 中间件
  → ZodValidationPipe（全局，校验 body，失败 422 envelope）
  → Controller（auth.controller）→ Guard（JwtAuthGuard 等）
  → Service（AuthService.adminLogin：锁定检查 → bcrypt → Turnstile → 签发双 token → 审计）
  → 成功：直接返回领域数据；失败：抛 BizException → AllExceptionsFilter → envelope
```

关键点：

- 输入校验收敛到 `@starter/contracts` 的 zod schema（`LoginSchema.parse`），失败抛 422。
- 业务异常用 `BizException`（`@starter/server-core`），由 `AllExceptionsFilter` 统一映射为 `{ success: false, error: { code, message, details? } }`。
- 未捕获异常兜底 `INTERNAL_SERVER_ERROR`，不泄露堆栈。

### 3.2 GraphQL 请求（如 `query me`）

```text
POST /graphql → Apollo Server（Code-First）
  → 全局限流守卫 GqlThrottlerGuard（兼容 GraphQL 上下文）
  → Resolver 参数经 ZodArgsPipe 校验（zod schema 生成 args 类型）
  → Service（与 REST 共用同一层！AuthService.me 等）
  → 错误统一映射：{ message, extensions: { code, fields } }
```

GraphQL 模块（`common/graphql/graphql.module.ts`）关键配置：

```ts
NestGraphQLModule.forRootAsync<ApolloDriverConfig>({
  driver: ApolloDriver,
  useFactory: (prisma: PrismaService) => ({
    autoSchemaFile: join(process.cwd(), 'graphql/schema.gql'), // Code-First 自动生成，勿手改
    sortSchema: true,
    introspection: process.env.NODE_ENV !== 'production', // 生产关内省
    context: ({ req, res }) => ({
      req,
      res,
      dataloaders: buildDataLoaders(prisma), // 每请求独立 DataLoader 实例
    }),
    formatError: (formattedError, error) => {
      const exception = unwrapResolverError(error) as { code?: string } | undefined;
      return {
        message: exception?.message ?? formattedError.message,
        extensions: {
          code: exception?.code ?? 'INTERNAL_SERVER_ERROR',
          fields: (formattedError.extensions ?? {}).fields ?? null,
        },
      };
    },
  }),
  inject: [PrismaService],
});
```

### 3.3 WebSocket 请求

socket.io 与 HTTP 同端口（3301），握手 middleware 校验 JWT（`WsJwtGuard`），事件示例：`ping → pong`、`whoami`、`notify`。连接数通过 `BusinessMetrics.activeConnections`（Gauge）监控。

## 4. GraphQL vs REST 决策

| 场景                    | 选择                       | 原因                                                        |
| ----------------------- | -------------------------- | ----------------------------------------------------------- |
| 管理端主要数据查询/变更 | **GraphQL**                | 树形/嵌套数据（菜单树、账户-角色-权限）按需取字段，一次拿全 |
| 认证（登录/登出/刷新）  | **REST**                   | 简单直白，便于与 Swagger/OpenAPI 集成、运维排查             |
| 文件上传                | **REST**（`POST /upload`） | multipart 上传，GraphQL 无原生支持                          |
| 健康检查                | **REST**（`/health`）      | Terminus 标准，探活用                                       |
| 第三方/内部集成         | **REST**                   | OpenAPI + orval 自动生成类型化 client                       |

**共用 Service 层**：REST Controller 与 GraphQL Resolver 都调用同一个业务 Service（如 `AuthService`、`UploadService`），保证逻辑单一、避免两套实现漂移。

**认证互通**：`JwtAuthGuard` 同时支持 REST 与 GraphQL（内部判断 `context.getType()`），权限守卫 `PermissionGuard` 同理，因此接口形态切换不引入安全差异。

## 5. 契约与数据流（单一事实来源）

```text
@starter/contracts（zod schema）
  ├─ 后端：ZodValidationPipe / ZodArgsPipe / Service 内 parse —— 运行时校验
  ├─ 后端：类型（LoginInput 等） —— 编译期类型
  └─ 前端：orval 生成的 client 消费 OpenAPI —— REST 类型（admin 禁止直接 import @starter/contracts）
```

约定：

- 输入输出形状先在 `contracts` 定义，再让两端消费，避免"前端一个样、后端一个样"。
- REST 契约经 `openapi/openapi.json` → orval → `@starter/api-client`（React Query hooks）传导；**应用层禁止直接 import `@starter/contracts`**（ESLint `no-restricted-imports` 强制），必须经 `@starter/api-client` 获取类型。
- GraphQL 类型由 Code-First 自动生成 `schema.gql`，前端（如需要）可经 codegen 生成 hooks。

## 6. N+1 优化（DataLoader）

菜单树、账户角色码等"循环查子项"的典型 N+1 场景，统一用 DataLoader 修复：

```ts
// common/dataloader/dataloader.factory.ts（节选）
export function buildDataLoaders(prisma: PrismaService): DataLoaders {
  return {
    roleCodesByAccountId: new DataLoader<string, string[]>(async (accountIds) => {
      const links = await prisma.client.adminAccountRole.findMany({
        where: { accountId: { in: accountIds } }, // 合并为单条 IN 查询
        select: { accountId: true, role: { select: { code: true, enabled: true } } },
      });
      return accountIds.map((id) => links.filter((l) => l.accountId === id && l.role.enabled).map((l) => l.role.code));
    }),
    // menuChildrenByParentId：单次查全量菜单后内存分组（菜单表 < 数百条）
  };
}
```

用法：resolver 中 `context.dataloaders.roleCodesByAccountId.load(accountId)`。每个请求独立实例，避免跨请求缓存污染。
