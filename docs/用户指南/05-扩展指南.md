# 05 扩展指南：三步新增一个业务功能

> 本文用完整示例（**公告模块 Notice**）演示新增业务功能的全流程：
> **① 后端（Prisma + Nest 模块 + Resolver）→ ② 契约（zod）→ ③ 前端页面**。
> 代码模式参照仓库现有模块（admin-role / system-dict 等），命名请遵守《docs/命名规范.md》。

## 0. 整体流程速览

```
后端: schema.prisma 加 model ── migrate dev ── modules/notice/（module/type/resolver/service）
      └── AppModule 注册 ── 重启 server ── 自动生成 graphql/schema.gql
契约: contracts/.../notice.ts ── index.ts 导出（前后端 import 同一类型）
前端: features/notices/ 页面 ── .graphql operations ── nx run @starter/admin:generate-graphql
      └── route-registry.tsx 注册路由 + admin_menu 加菜单记录
```

---

## 第 1 步：后端（数据库 + 模块 + Resolver）

### 1.1 添加 Prisma 模型

编辑 `apps/server/prisma/schema.prisma`，追加（示例）：

```prisma
model Notice {
  id        String   @id @default(uuidv7())   // 主键约定统一 uuidv7()
  title     String
  content   String
  published Boolean  @default(false)
  createdAt DateTime @default(now())
  updatedAt DateTime @updatedAt
}
```

生成并应用迁移：

```bash
cd apps/server && pnpm exec prisma migrate dev --name add_notice && cd ../..
```

### 1.2 创建模块

目录 `apps/server/src/modules/notice/`，4 个文件（`notice.module.ts` / `notice.type.ts` / `notice.resolver.ts` / `notice.service.ts`）。

`notice.type.ts`（GraphQL 对象类型）：

```ts
import { Field, ID, ObjectType } from '@nestjs/graphql';

@ObjectType()
export class NoticeType {
  @Field(() => ID) id: string;
  @Field() title: string;
  @Field() content: string;
  @Field() published: boolean;
  @Field() createdAt: Date;
}
```

`notice.service.ts`（业务逻辑，注入 PrismaService）：

```ts
import { Injectable } from '@nestjs/common';
import { PrismaService } from '../../common/prisma/prisma.service.js';

@Injectable()
export class NoticeService {
  constructor(private readonly prisma: PrismaService) {}

  list() {
    return this.prisma.client.notice.findMany({ orderBy: { createdAt: 'desc' } });
  }
}
```

`notice.resolver.ts`（GraphQL 入口，挂 JWT + 权限守卫）：

```ts
import { UseGuards } from '@nestjs/common';
import { Query, Resolver } from '@nestjs/graphql';
import { JwtAuthGuard } from '../auth/jwt-auth.guard.js';
import { PermissionGuard } from '../auth/permission.guard.js';
import { RequirePermission } from '../auth/permission.decorator.js';
import { NoticeService } from './notice.service.js';
import { NoticeType } from './notice.type.js';

@Resolver()
@UseGuards(JwtAuthGuard, PermissionGuard)
export class NoticeResolver {
  constructor(private readonly noticeService: NoticeService) {}

  @Query(() => [NoticeType])
  @RequirePermission('notice:list') // ← 权限点，需在 admin_menu 里登记
  notices() {
    return this.noticeService.list();
  }
}
```

`notice.module.ts`：`@Module({ providers: [NoticeResolver, NoticeService] })` 导出 `NoticeModule`（与现有模块一致）。

### 1.3 注册并验证

在 `apps/server/src/app/app.module.ts` 的 `imports: [...]` 中加入 `NoticeModule`，重启：

```bash
pnpm exec nx serve server
```

启动后 `graphql/schema.gql` 自动重新生成，应出现 `Notice` 类型与 `notices` query。到 http://localhost:3301/graphql 执行 `{ notices { id title } }` 验证（需登录 token；`super_admin` 自动绕过权限，可先测通再登记权限点）。

## 第 2 步：契约（zod，前后端共享）

仅当功能有需要**跨端共享校验**的结构（分页入参、表单出参等）时才建契约；纯 GraphQL 功能第 1 步的类型已够用。

新建 `packages/shared/contracts/src/lib/schemas/notice.ts`：

```ts
import { z } from 'zod';

export const NoticeSchema = z.object({
  id: z.string(), // 主键 UUIDv7，由后端生成
  title: z.string().min(1).max(100),
  content: z.string(),
  published: z.boolean().default(false),
});

export type Notice = z.infer<typeof NoticeSchema>;
```

在 `packages/shared/contracts/src/index.ts` 导出：`export * from './lib/schemas/notice.js';`

用法：

- 后端：`nestjs-zod` 的 `ZodValidationPipe`（REST）/ `ZodArgsPipe`（GraphQL）校验入参；
- 前端：`import type { Notice } from '@starter/contracts'`。

## 第 3 步：前端页面

### 3.1 建 feature 目录 + 页面骨架

```
apps/admin/src/features/notices/
└── pages/notices-page.tsx
```

```tsx
export function NoticesPage() {
  // 数据层二选一：useQuery（REST hooks）或 useNoticesQuery（Apollo codegen hooks）
  return <div>公告列表</div>;
}
```

### 3.2 生成类型化 hooks（GraphQL 场景）

在 feature 目录写 operations，例如 `apps/admin/src/features/notices/notices.graphql`：

```graphql
query Notices {
  notices {
    id
    title
    content
    published
  }
}
```

重新生成 hooks（命令见 `apps/admin/codegen.ts` 顶部注释），产物落到 `apps/admin/src/generated/graphql.ts`：

```bash
pnpm exec nx run @starter/admin:generate-graphql
```

> REST 场景改完后端 DTO 后依次运行：`pnpm exec nx run server:generate-openapi`（重新发射 OpenAPI）→ `pnpm generate:api`（orval 重新生成 client，产物在 `packages/shared/api-client/src/generated/`）。

### 3.3 注册路由 + 菜单

`apps/admin/src/app/route-registry.tsx` 注册一行（含权限点）：

```tsx
{ path: '/admin/notices', element: <NoticesPage />, permission: 'notice:list' },
```

侧栏菜单来自后端 `me.menus`（数据在 `admin_menu` 表）：用「菜单管理」页面新增菜单记录（或在 `apps/server/prisma/seed.ts` 的菜单数组补充），`path` 必须与 route-registry 一致；给目标角色勾选该菜单后权限点生效。

### 3.4 验证与收尾

1. 访问 http://localhost:3302/admin/notices，确认侧栏出现「公告管理」、页面正常请求数据；
2. 跑门禁：`pnpm lint`、`pnpm typecheck`、`pnpm test`；
3. 提交前运行 `pnpm bump`（见 08-Changelog）。
