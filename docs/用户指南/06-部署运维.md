# 06 部署运维

> Docker 构建 / Compose 编排（开发 + 生产）/ K8s 部署 / 健康检查 / 日志 / 监控指标。
> 所有部署资产都在仓库根目录：`docker-compose.yml`、`docker-compose.prod.yml`、`k8s/`、`apps/*/Dockerfile`。

---

## 1. 镜像构建

后端（NestJS webpack 产物，多阶段构建）：

```bash
docker build -f apps/server/Dockerfile -t monorepo-starter-server .
```

管理端（Vite 构建 + nginx 静态服务与反代）：

```bash
docker build -f apps/admin/Dockerfile -t monorepo-starter-admin .
```

> 构建时间较长是正常的（Stage 1 全量安装依赖含 prisma/swc 等构建工具）；镜像内 Node 22 + pnpm 11 由 corepack 锁定。
> server 镜像运行时非 root 用户（UID 1001）+ dumb-init，PID 1 能正确响应 SIGTERM（k8s 优雅关闭依赖它）。

## 2. 开发编排（docker compose up）

`docker-compose.yml` 起 **postgres / redis / server / admin / adminer** 五个服务：

```bash
docker compose up -d            # 默认端口即可（见下）
docker compose ps               # 查看状态
docker compose logs -f server   # 跟随后端日志
```

| 服务     | 端口（宿主机） | 说明                                      |
| -------- | -------------- | ----------------------------------------- |
| postgres | 127.0.0.1:5432 | PG 17，健康检查 `pg_isready`              |
| redis    | 127.0.0.1:6379 | Redis 7                                   |
| server   | 127.0.0.1:3301 | 开发编排内 `develop.watch` 同步源码热重载 |
| admin    | 127.0.0.1:3302 | nginx 静态服务 + 反代                     |
| adminer  | 127.0.0.1:8080 | 数据库管理（**dev-only**）                |

自定义端口/凭据通过根目录 `.env`（模板 `.env.example`）覆盖：

```bash
cp .env.example .env
# 改 SERVER_PORT / ADMIN_PORT / POSTGRES_PASSWORD 等
docker compose up -d
```

> 端口只绑定 `127.0.0.1`（不暴露公网）；server 依赖 postgres/redis 健康后才启动。

## 3. 生产编排（docker compose -f docker-compose.prod.yml）

生产编排**不含 adminer**，全部服务限制资源（cpus/memory/pids_limit）、`no-new-privileges`、非 root 运行、只读根文件系统 + tmpfs。

```bash
# 1) 准备生产环境变量（必填项缺失会启动失败）
cat > .env.production <<'EOF'
POSTGRES_PASSWORD=<强密码>
JWT_SECRET=<至少16字符随机串>
CORS_ORIGINS=https://admin.example.com
IMAGE_REGISTRY=ghcr.io
IMAGE_REPOSITORY_OWNER=your-org
IMAGE_TAG=latest
LOG_LEVEL=info
EOF

# 2) 启动
docker compose -f docker-compose.prod.yml --env-file .env.production up -d

# 3) 查看状态与日志
docker compose -f docker-compose.prod.yml --env-file .env.production ps
docker compose -f docker-compose.prod.yml --env-file .env.production logs -f server
```

要点：

- `JWT_SECRET` 与 `POSTGRES_PASSWORD` 用 `${VAR:?}` 声明 —— **不设置直接启动失败**（fail-fast，防止弱默认值上线）；
- 生产编排使用**已推送的镜像**（`IMAGE_REGISTRY/IMAGE_REPOSITORY_OWNER/IMAGE_TAG`），不走本地 build；
- server 的健康检查打 `/health/readiness`（依赖 DB，比 dev 的 `/health` 更严格）。

数据库迁移（首次或版本升级时）：

> server 镜像已包含 `prisma` 目录（schema + migrations，Dockerfile 注释注明"运行时 deploy 用"），因此迁移在部署流程里执行：

```bash
# 方式一：进入运行中的 server 容器执行（需镜像内可调用 prisma CLI）
docker compose -f docker-compose.prod.yml --env-file .env.production exec server \
  pnpm exec prisma migrate deploy

# 方式二（推荐）：在 CI 流水线里，于镜像构建后 / 滚动部署前执行 migrate deploy
```

> 迁移命令的具体调用方式以镜像内可用的工具为准（prod 依赖安装下 prisma CLI 的可用性随镜像变化）；原则是**先迁移、后起新副本**，且 `migrate deploy` 只应用迁移、不修改 schema。

## 4. Kubernetes 部署

`k8s/` 目录提供 kustomize manifests：

```
k8s/
├── namespace.yaml            # monorepo-starter 命名空间
├── postgres-statefulset.yaml # PostgreSQL（含 headless service）
├── postgres-pvc.yaml         # PG 持久卷声明
├── redis-statefulset.yaml    # Redis
├── server-deployment.yaml    # 后端 Deployment（探针 / 资源 / 优雅关闭）
├── admin-deployment.yaml     # 管理端 Deployment
├── ingress.yaml              # 入口（server + admin 路由）
└── kustomization.yaml        # 汇总入口
```

一键部署：

```bash
kubectl apply -k k8s/
kubectl -n monorepo-starter get pods        # 观察 Pod 就绪
kubectl -n monorepo-starter logs -f deploy/server
```

要点：

- **前置依赖**（见 `k8s/kustomization.yaml` 顶部注释）：cert-manager + letsencrypt-prod ClusterIssuer（TLS 自动签发）、Nginx Ingress Controller、metrics-server；
- **Secret / ConfigMap**：server 的 `envFrom` 引用 `server-config`（ConfigMap）与 `server-secrets`（Secret）；postgres 凭据用 `postgres-credentials`（kustomization 注释给出创建命令：`kubectl create secret generic postgres-credentials --from-literal=username=postgres --from-literal=password=...`）。上线前按这些名字创建并填入真实值；
- **镜像 tag 占位**：manifests 里是 `<registry>/monorepo-starter-server:<tag>` 占位，构建推送后用 `kubectl kustomize ... | kubectl apply -f -` 或 `kustomize edit set image` 换成真实镜像；
- **探针**：server 配置了 liveness（`/health/liveness`，进程存活）+ readiness（`/health/readiness`，DB + 内存探活）+ startup 探针 —— 依赖挂了不重启容器，而是摘流量等恢复；
- **数据持久化**：postgres / redis 用 StatefulSet + PVC；
- 生产环境数据库迁移建议在滚动前手动执行 `prisma migrate deploy`（见第 3 节）。

## 5. 健康检查端点

| 端点                    | 用途                                                          | 依赖                   |
| ----------------------- | ------------------------------------------------------------- | ---------------------- |
| `GET /health`           | 基础信息（service / version），前端展示用                     | 无                     |
| `GET /health/liveness`  | 存活探针（livenessProbe）：进程活着即 200                     | 无（**不查外部依赖**） |
| `GET /health/readiness` | 就绪探针（readinessProbe）：DB `SELECT 1` + 内存 heap < 300MB | PostgreSQL             |
| `GET /healthz`          | admin 容器 nginx 健康检查（wget 探测）                        | 无                     |

验证：

```bash
curl -s http://localhost:3301/health
curl -s http://localhost:3301/health/liveness
curl -s http://localhost:3301/health/readiness   # 依赖 DB 就绪
```

## 6. 日志

- 后端使用 **pino 结构化日志**（JSON 行），requestId 串联请求链路；级别由 `LOG_LEVEL` 控制；
- 本地开发：直接看终端；容器：`docker compose logs -f server` / `kubectl -n monorepo-starter logs -f deploy/server`；
- 生产建议接入集中日志（如 Loki/ELK），把容器 stdout 采集走即可，无需改代码；
- 排障常用：`docker compose logs --tail=200 server`、`kubectl describe pod <pod>`（看探针/镜像拉取失败原因）。

---

## 7. 监控指标（Prometheus）

- 端点：`GET /metrics`（`@willsoto/nestjs-prometheus`，含 Node.js 运行时默认指标）；
- 业务指标（`common/metrics/business.metrics.ts`）：登录失败计数、限流拦截计数、审计写入计数、上传计数、缓存命中率等 —— 业务代码注入 `BusinessMetrics` 后调用语义方法埋点；
- 接入方式：Prometheus 抓取 `http://<server>:3301/metrics`，Grafana 出面板；CI 里可用 Trivy/审计任务保证镜像安全（见 08-Changelog 的 CI 全链路）。

## 8. 常用运维速查

| 操作           | 命令                                                                         |
| -------------- | ---------------------------------------------------------------------------- |
| 本地起全套 dev | `docker compose up -d`                                                       |
| 起生产编排     | `docker compose -f docker-compose.prod.yml --env-file .env.production up -d` |
| 看日志         | `docker compose logs -f server`（生产编排加 `-f ... --env-file` 参数）       |
| 重建某服务     | `docker compose up -d --build server`                                        |
| 停止/清理      | `docker compose down`（`-v` 会删数据卷，慎用）                               |
| 生产迁移       | 容器内 `prisma migrate deploy`（见第 3 节）                                  |
| K8s 部署       | `kubectl apply -k k8s/`                                                      |
| 健康检查       | `curl http://localhost:3301/health/readiness`                                |
| 监控           | `curl http://localhost:3301/metrics`                                         |
