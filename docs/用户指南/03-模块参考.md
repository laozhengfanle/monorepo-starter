# 03 模块参考

> 后端每个业务模块（`apps/server/src/modules/*`）与前端每个 feature（`apps/admin/src/features/*`）的职责说明。
> 定位代码时以本表为索引；模块内结构约定：`*.module.ts` 装配、`*.resolver.ts` GraphQL 入口、`*.service.ts` 业务逻辑、`*.type.ts` GraphQL 类型、`*.controller.ts` REST 入口。

---

## 1. 后端模块（apps/server/src/modules）

### 1.1 auth —— 认证与授权（核心）

| 文件                                              | 职责                                                                |
| ------------------------------------------------- | ------------------------------------------------------------------- |
| `auth.resolver.ts` / `auth.controller.ts`         | GraphQL mutation（login / me 等）+ REST 登录端点                    |
| `auth.service.ts`                                 | 登录校验（bcrypt）、JWT 签发（含 jti + tokenVersion）、退出登录     |
| `jwt-auth.guard.ts`                               | 全局 JWT 守卫：验签 + jti 黑名单 + tokenVersion 撤销校验            |
| `permission.guard.ts` / `permission.decorator.ts` | `@RequirePermission('xxx:yyy')` 权限点校验                          |
| `login-lock.service.ts`                           | 登录失败锁定：账号 5 次/15min、同 IP 50 次/15min（阈值可配，见 04） |
| `token-blacklist.service.ts`                      | 退出/改密后撤销 token（jti 黑名单 + tokenVersion）                  |
| `token-issuance.service.ts`                       | access token 签发（JWT_ACCESS_TTL，默认 900 秒）                    |
| `audit.service.ts` + `audit.constants.ts`         | 审计写入（fail-open，不阻塞主流程）                                 |

### 1.2 admin-account —— 管理员账号

账号 CRUD、启停用、分配角色、重置密码、修改个人资料（`me`）。关联 `AdminProfile` / `AdminAccountRole` / `AdminAccountMenu` 表，软删除闭环（列表集成 + 回收站 + 恢复/彻底删除）。

### 1.3 admin-role —— 角色与权限

角色 CRUD、角色-菜单-权限点绑定（`AdminRoleMenu`）、权限点分配。角色被账号引用时删除需校验，特例授权（允许/禁止）有按钮颜色区分。

### 1.4 admin-menu —— 菜单树

菜单树维护（增删改排序、父子层级）、按角色输出可见菜单（`me.menus`）、全局权限隐藏目录（`global:trash:*` 等）。N+1 由 DataLoader 批量查询解决。

### 1.5 audit-log —— 审计日志

查询审计日志（分页、按操作人/动作/结果过滤）。审计写入由 `auth/audit.service.ts` 统一完成，本模块只读查询；仪表盘的分析区块也复用其数据。

### 1.6 cache-admin —— 缓存管理

查看缓存统计（命中率等）、按 key / 通配符模式删除缓存。操作对象是 `CACHE_SERVICE_TOKEN` 抽象，Redis 与内存降级后端都支持。

### 1.7 dashboard —— 仪表盘

只读聚合（BFF 规范）：统计卡片（登录可见）、敏感操作趋势（周/月/年）、操作类型分布、最近操作记录。分析区块复用 `config:audit:view` 权限，无需新增权限点。

### 1.8 file-manager —— 文件管理

文件列表、上传记录查询、删除。底层走 `common/storage` 的可插拔存储驱动（当前 `local-storage.driver.ts`，可扩展 S3/OSS），元数据落 `UploadFile` 表。

### 1.9 system-config —— 系统设置

键值配置（`SystemConfig` 表），承载 `settings.loginFailThreshold`、`turnstile.config` 等业务配置；提供类型安全的读取/写入，供登录锁定、Turnstile 等模块回退读取。

### 1.10 system-dict —— 字典管理

字典类型与字典项（`SysDictType` / `SysDictItem`）维护，供下拉选项等场景使用。

### 1.11 turnstile —— Cloudflare Turnstile 人机验证

配置来源优先级：`system_config.turnstile.config` → 环境变量 → 跳过；校验链路：测试密钥快速通道 → dev 本地 bypass → Redis 防重放 → Cloudflare siteverify。登录页集成。

### 1.12 upload —— 文件上传（REST）

REST 上传端点（multer），存储到 `UPLOAD_DIR`（默认 `uploads/`），通过 `/uploads/{storedName}` 静态访问；记录 `UploadFile` 元数据并埋点上传计数指标。

### 1.13 ws —— WebSocket 网关

socket.io 网关（与 HTTP 同端口 3301），握手时校验 JWT（`ws-jwt.guard.ts`），示例事件 `ping/pong`、`whoami`、`notify`；面向后续实时通知扩展。

### 1.14 health（src/health，非 modules）

- `GET /health`：基础信息（service / version，前端 dashboard 用）；
- `GET /health/liveness`：进程存活探针（无外部依赖）；
- `GET /health/readiness`：terminus 就绪探针（DB `SELECT 1` + 内存 heap < 300MB）。

## 2. 公共基建（apps/server/src/common）

| 目录             | 职责                    | 备注                                                                                                |
| ---------------- | ----------------------- | --------------------------------------------------------------------------------------------------- |
| `prisma/`        | PrismaService           | PostgreSQL + UUIDv7，driver adapter                                                                 |
| `cache/`         | 缓存抽象                | Redis → 内存降级，全局 `CACHE_SERVICE_TOKEN`                                                        |
| `graphql/`       | Code-First GraphQL 模块 | Apollo、自动生成 `graphql/schema.gql`、DataLoader、错误归一化 `{message, extensions:{code,fields}}` |
| `dataloader/`    | DataLoader 工厂         | 每请求独立实例，菜单树/角色码批量加载                                                               |
| `logger/`        | pino 结构化日志         | requestId 串联，LOG_LEVEL 可配                                                                      |
| `metrics/`       | Prometheus 指标         | `/metrics` 端点 + BusinessMetrics（登录失败/限流/审计/上传/缓存命中）                               |
| `notifications/` | 短信 / 邮件通知         | Provider 可插拔，默认 mock                                                                          |
| `storage/`       | 存储驱动抽象            | 当前 LocalStorageDriver，可扩展                                                                     |
| `tasks/`         | 定时任务                | 每日清理过期审计日志与 token 撤销记录                                                               |
| `throttler/`     | 全局限流                | 100 次/分钟/IP，GraphQL 兼容守卫                                                                    |

### 前端公共层（apps/admin/src/app）

| 文件                      | 职责                                                                                               |
| ------------------------- | -------------------------------------------------------------------------------------------------- |
| `apollo-client.ts`        | Apollo Client 实例（GraphQL 数据层）                                                               |
| `route-registry.tsx`      | **路由注册表**：`path → 页面组件 + 权限点`；新增页面 = 注册一行 + 后端 `admin_menu` 加一条菜单记录 |
| `auth/use-permission.ts`  | 权限判断 hooks（菜单显隐 + 路由守卫 403 兜底）                                                     |
| `layouts/` / `providers/` | 布局骨架与全局 Provider（QueryClient / Apollo / antd `App`）                                       |
| `version.ts`              | 应用版本**单一来源**（`pnpm bump` 维护，勿手改）                                                   |
