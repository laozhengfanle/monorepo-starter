# 01 快速上手

> 面向新加入的开发者。按本指南操作，大约 10 分钟即可在本地跑起完整的前后端环境。
> 全部命令在项目根目录执行（除非特别说明）。

---

## 1. 环境准备

| 依赖           | 要求                               | 说明                                                               |
| -------------- | ---------------------------------- | ------------------------------------------------------------------ |
| Node.js        | `>= 22.18`（推荐 24 LTS）          | 根 `package.json` 的 `engines` 声明了最低版本，过低会安装/构建失败 |
| pnpm           | `11.21.0`                          | 仓库用 `packageManager: pnpm@11.21.0` 锁定版本                     |
| PostgreSQL     | 本地 14+，或用 Docker（见第 3 步） | 业务数据库，Prisma 连接                                            |
| Docker（可选） | 任意较新版本                       | 一键拉起 postgres / redis / adminer                                |

检查当前环境：

```bash
node -v        # 应 >= v22.18.0
pnpm -v        # 应显示 11.21.0
```

如果 pnpm 版本不对，用 corepack 激活仓库锁定版本：

```bash
corepack enable
corepack prepare pnpm@11.21.0 --activate
```

> 若 corepack 下载慢，也可直接 `npm i -g pnpm@11.21.0`。

---

## 2. 安装依赖

```bash
pnpm install
```

- 仓库是 pnpm workspace + Nx 23 的 monorepo，一次安装会装好 `apps/*` 与 `packages/**` 全部依赖。
- 依赖版本统一由 `pnpm-workspace.yaml` 里的 **catalog** 管理，`catalogMode: strict` 已开启，因此**不要**直接 `pnpm add <包>` 装 catalog 之外的包（会报错，见第 7 节常见坑）。

---

## 3. 配置环境变量

后端需要一份 `.env`，从模板复制：

```bash
cp apps/server/.env.example apps/server/.env
```

默认模板已经可以直接连接本地 PostgreSQL（`postgresql://postgres:postgres@localhost:5432/monorepo_starter?schema=public`），仅需确认两点：

1. 本地 PostgreSQL 已启动，且 `postgres` 用户密码是 `postgres`（或改 `.env` 里的 `DATABASE_URL`）；
2. 如果本机没有 PostgreSQL，直接用 Docker 拉起（推荐，后面 Redis 也会用到）：

```bash
docker compose up -d postgres redis adminer
# postgres: 127.0.0.1:5432, redis: 127.0.0.1:6379, adminer: 127.0.0.1:8080
```

> 生产环境务必修改 `JWT_SECRET`（至少 16 字符）。开发环境用模板默认值即可。

---

## 4. 数据库初始化（迁移 + 种子数据）

```bash
cd apps/server
pnpm exec prisma migrate dev
pnpm exec prisma db seed
cd ../..
```

- `migrate dev`：根据 `apps/server/prisma/schema.prisma` 生成/应用迁移（首次会自动创建所有表）；`db seed`：写入初始管理员账号、角色、菜单、字典等种子数据（见 `apps/server/prisma/seed.ts`）。
- 根目录脚本 `pnpm db:migrate` / `pnpm db:seed` 效果相同（见第 8 节命令表）。

---

## 5. 启动前后端

两个终端分别执行：

```bash
# 终端 1：后端（端口 3301）
pnpm exec nx serve server

# 终端 2：前端（端口 3302）
pnpm exec nx serve admin
```

> 两个终端都保持运行。`nx serve` 是开发模式：server 端 webpack 热重载，admin 端 Vite dev server 热更新。

启动成功后你会有：

| 入口                                 | 地址                           |
| ------------------------------------ | ------------------------------ |
| 管理后台                             | http://localhost:3302          |
| GraphQL Playground（Apollo Sandbox） | http://localhost:3301/graphql  |
| Swagger API 文档                     | http://localhost:3301/api-docs |
| 健康检查                             | http://localhost:3301/health   |

---

## 6. 验证环境

1. 浏览器打开 **http://localhost:3302**，应看到登录页；
2. 用种子数据里的管理员账号密码登录（具体账号见 `apps/server/prisma/seed.ts`，默认通常是 `admin`）；
3. 登录后进入仪表盘，能看到统计卡片与趋势图，说明前后端 + GraphQL + 数据库链路全部打通；
4. 打开 http://localhost:3301/health，应返回 `{ "service": "...", "version": "0.1.25", ... }` 之类的基础信息。

跑一遍质量门禁，确认工具链正常：

```bash
pnpm lint            # oxlint 代码检查
pnpm typecheck       # 全仓 TypeScript 类型检查
pnpm test            # 全仓 Vitest 单元测试
pnpm build           # 全仓构建
pnpm e2e             # Playwright 端到端（需先启动 server + admin）
```

## 7. 常见坑

### 7.1 Node 版本过低

报错形如 `Unsupported engine: node@v20.x ... wanted: {"node":">=22.18.0"}`（pnpm 默认会拦截）。

解决：用 nvm / fnm 安装 Node 24：

```bash
nvm install 24 && nvm use 24
```

### 7.2 pnpm 版本不对 / corepack 报错

报错形如 `Your pnpm version X is incompatible with ...`。

解决：

```bash
corepack enable
corepack prepare pnpm@11.21.0 --activate
```

### 7.3 `catalogMode: strict` 导致 `pnpm add` 失败

`pnpm add <包>` 报错：**`<包> is not in the catalog`**（或类似 "not allowed" 提示）。这是预期行为：仓库要求所有依赖版本统一登记在 `pnpm-workspace.yaml` 的 `catalog` 段。

正确做法：

1. 打开 `pnpm-workspace.yaml`，在 `catalog:` 下新增一行 `<包名>: <版本范围>`；
2. 再执行 `pnpm install`；
3. 最后在具体包的 `package.json` 里通过 `catalog:` 语法引用（`"<包>": "catalog:"`）。

> 不要用 `pnpm add` 绕过 —— CI 里 `pnpm install --frozen-lockfile` 会再次失败。

### 7.4 数据库连接失败

`migrate dev` 或启动 server 时报 `Can't reach database server` / `Connection refused`。

排查顺序：

1. 本地 PG 是否在跑：`pg_isready` 或 `docker ps`；
2. `apps/server/.env` 的 `DATABASE_URL` 是否与本机一致（端口、用户名、密码、库名）；
3. 没装 PG 就用 `docker compose up -d postgres`。

### 7.5 端口被占用

server 启动报 `EADDRINUSE` / admin 打不开。找出占用进程并释放：

```bash
lsof -i :3301   # macOS/Linux
# 或 Windows: netstat -ano | findstr 3301
```

改端口的方法见《04-配置参考.md》。

### 7.6 种子账号密码忘了

`pnpm db:seed` 是幂等脚本，可重复执行恢复初始数据；账号密码都定义在 `apps/server/prisma/seed.ts`，以文件里的值为准（不要在文档里猜）。

### 7.7 改了代码 GraphQL 没生效

`schema.gql` 是后端启动时自动生成的**生成物**（`graphql/schema.gql`），改完 Resolver 需要重启 server 才会重新生成并生效。详见《07-故障排查.md》第 3 节。

## 8. 常用命令速查

| 命令                                                                     | 作用                                   |
| ------------------------------------------------------------------------ | -------------------------------------- |
| `pnpm exec nx serve server` / `... serve admin`                          | 启动后端 / 前端（开发模式）            |
| `pnpm build` / `pnpm test` / `pnpm lint` / `pnpm typecheck` / `pnpm e2e` | 构建 / 测试 / 检查 / 类型 / 端到端     |
| `pnpm lint:boundaries`                                                   | ESLint 模块边界检查（Nx 依赖规则）     |
| `pnpm db:migrate` / `pnpm db:deploy` / `pnpm db:seed` / `pnpm db:studio` | 迁移 / 生产迁移 / 种子 / Prisma Studio |
| `pnpm generate:api`                                                      | 重新生成 orval REST client（见 05/07） |
| `pnpm erd:generate`                                                      | 生成 ER 图（docs/erd.md）              |
| `pnpm bump`                                                              | 版本递增 + 提交 + 打标签（见 08）      |
