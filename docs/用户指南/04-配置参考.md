# 04 配置参考

> 环境变量、Docker 编排变量、Nx 配置与端口修改方法。所有变量都有默认值或模板示例，照着复制即可。

---

## 1. 后端环境变量（apps/server/.env）

模板：`apps/server/.env.example`。启动时由 `src/config/env.validation.ts` 全量校验，**任何缺失/非法配置都会 fail-fast**（报错信息形如 `环境变量校验失败: xxx: ...`）。

| 变量                           | 默认值                                                                         | 说明                                                                           |
| ------------------------------ | ------------------------------------------------------------------------------ | ------------------------------------------------------------------------------ |
| `NODE_ENV`                     | `development`                                                                  | `development` / `test` / `production`；`production` 下关闭 GraphQL 内省        |
| `PORT`                         | `3301`                                                                         | 后端监听端口                                                                   |
| `LOG_LEVEL`                    | `log`                                                                          | pino 日志级别：`fatal`/`error`/`warn`/`log`/`debug`/`verbose`                  |
| `DATABASE_URL`                 | `postgresql://postgres:postgres@localhost:5432/monorepo_starter?schema=public` | PostgreSQL 连接串（Prisma driver adapter 使用，**必填**）                      |
| `CORS_ORIGINS`                 | `http://localhost:3302`                                                        | 允许跨域的 origin，**逗号分隔**；不配置时默认仅放行 admin 开发地址             |
| `JWT_SECRET`                   | 模板里为占位符                                                                 | JWT 签名密钥，**至少 16 字符**，生产必须改为强随机值                           |
| `JWT_ACCESS_TTL`               | `900`                                                                          | access token 有效期（秒），900 = 15 分钟                                       |
| `LOGIN_LOCK_ACCOUNT_THRESHOLD` | `5`                                                                            | 账号登录失败锁定阈值（次/15min）                                               |
| `LOGIN_LOCK_IP_THRESHOLD`      | `50`                                                                           | 同 IP 登录失败锁定阈值（次/15min）                                             |
| `LOGIN_LOCK_TTL`               | `900`                                                                          | 锁定持续时间（秒）                                                             |
| `NOTIFY_SMS_PROVIDER`          | `mock`                                                                         | 短信 Provider：`mock`（可扩展 `aliyun`/`tencent`）                             |
| `NOTIFY_EMAIL_PROVIDER`        | `mock`                                                                         | 邮件 Provider：`mock`（可扩展 `smtp`/`ses`）                                   |
| `REDIS_URL`                    | 未配置时降级                                                                   | Redis 连接串（`redis://redis:6379` 形式）；**不可用时缓存自动降级内存后端**    |
| `UPLOAD_DIR`                   | `uploads`                                                                      | 上传文件目录（与 `app-setup.ts` 的静态目录一致）                               |
| `OPENAPI_OUT_PATH`             | 无                                                                             | 设置后启动时发射 OpenAPI JSON 到该路径并退出（orval 生成用，一般不走手动设置） |

> 注意：`LOGIN_LOCK_ACCOUNT_THRESHOLD` 的生效优先级低于后台设置 —— 若 `system_config` 的 `settings.loginFailThreshold` 已配置，以后台为准（见 03 模块参考）。

## 2. Docker 编排变量（根 .env）

模板：根目录 `.env.example`。`docker compose` 读取（`${VAR:-默认值}` 语法），与后端 `.env` 是**两套独立文件**。

| 变量                     | 默认值                                       | 说明                                                                    |
| ------------------------ | -------------------------------------------- | ----------------------------------------------------------------------- |
| `SERVER_PORT`            | `3301`                                       | server 容器映射到宿主机的端口                                           |
| `ADMIN_PORT`             | `3302`                                       | admin 容器映射到宿主机的端口                                            |
| `POSTGRES_PORT`          | `5432`                                       | postgres 容器映射端口                                                   |
| `REDIS_PORT`             | `6379`                                       | redis 容器映射端口                                                      |
| `ADMINER_PORT`           | `8080`                                       | adminer 容器映射端口（仅开发编排）                                      |
| `POSTGRES_USER`          | `postgres`                                   | PG 用户（开发默认；生产必须改）                                         |
| `POSTGRES_PASSWORD`      | `postgres`                                   | PG 密码（开发默认；生产必填强密码）                                     |
| `POSTGRES_DB`            | `monorepo_starter`                           | PG 库名                                                                 |
| `JWT_SECRET`             | 占位符                                       | 生产编排里 `${JWT_SECRET:?JWT_SECRET 必填}` —— **不设置会直接启动失败** |
| `IMAGE_REGISTRY`         | `ghcr.io`                                    | 生产编排拉取的镜像仓库                                                  |
| `IMAGE_REPOSITORY_OWNER` | `your-org`                                   | 镜像仓库所属组织/用户                                                   |
| `IMAGE_TAG`              | `latest`                                     | 镜像 tag                                                                |
| `CORS_ORIGINS`           | `https://admin.example.com`                  | 生产编排传给 server 的跨域白名单                                        |
| `LOG_LEVEL`              | `info`                                       | 生产编排传给 server 的日志级别                                          |
| `COMPOSE_PROJECT_NAME`   | `monorepo-starter` / `monorepo-starter-prod` | compose 项目名前缀                                                      |

用法：

```bash
cp .env.example .env            # 可选：自定义端口/密码
docker compose up -d            # 开发编排读取 .env（默认值即可跑）
```

生产环境参考《06-部署运维.md》创建 `.env.production`。

## 3. Nx 配置（nx.json）

Nx 23 的 target（`build` / `serve` / `dev` / `test` / `typecheck` / `e2e` 等）由**插件推断**（`@nx/webpack/plugin`、`@nx/vite/plugin`、`@nx/react/router-plugin`、`@nx/vitest`、`@nx/playwright/plugin`），没有手写的 `project.json`。

关键配置：

| 配置段           | 内容                                                                                   |
| ---------------- | -------------------------------------------------------------------------------------- |
| `plugins`        | 各框架插件的 target 命名映射（如 vite `devTargetName: dev`、`serveTargetName: serve`） |
| `namedInputs`    | `default` / `production` / `sharedGlobals`：构建缓存输入定义                           |
| `targetDefaults` | `test` 依赖 `^build`；vite/js:tsc 构建缓存开启                                         |
| `generators`     | 脚手架默认值（react 应用用 vite + css，style 为 css 等）                               |
| `analytics`      | `false`                                                                                |

常用命令（一律经 `pnpm exec nx ...`）：

```bash
pnpm exec nx show projects                    # 列出全部项目
pnpm exec nx show project server              # 查看 server 的 targets/依赖
pnpm exec nx run-many -t build                # 全仓构建
pnpm exec nx affected -t test                 # 只跑受影响的测试
pnpm exec nx graph                            # 打开依赖图
```

> 不要直接调用底层工具（`vite build` / `tsc` / `vitest`），统一走 nx 以享受缓存与依赖编排。

## 4. 如何修改端口

### 4.1 修改后端端口

1. 改 `apps/server/.env` 的 `PORT=3301` → 新端口；
2. 如果开发代理要跟着变，同步改 admin 的代理目标（见 4.2）。

> `app-setup.ts` 里 `DEFAULT_PORT = 3301` 只是未配置时的兜底值，配了 `PORT` 即生效。

### 4.2 修改前端端口

编辑 `apps/admin/vite.config.mts`：

```ts
server: {
  port: 3302,            // ← 改这里
  host: '0.0.0.0',
  proxy: {
    '/api':     { target: 'http://localhost:3301', ... },   // ← 后端地址变了也要改
    '/graphql': { target: 'http://localhost:3301', ... },
    '/uploads': { target: 'http://localhost:3301', ... },
  },
},
```

### 4.3 修改 Docker 编排端口

不需要改任何文件 —— 用根目录 `.env` 的变量覆盖：

```bash
SERVER_PORT=3311 ADMIN_PORT=3312 docker compose up -d
```

生产编排同理：`.env.production` 里写 `SERVER_PORT` / `ADMIN_PORT` 等。

### 4.4 修改 CORS 白名单

后端默认只放行 `http://localhost:3302`。前端改了端口（如 3312）后必须同步：

```bash
# apps/server/.env
CORS_ORIGINS=http://localhost:3312
```

多个来源用逗号分隔：`CORS_ORIGINS=http://localhost:3302,https://admin.example.com`。

## 5. 校验配置是否生效

```bash
# 后端启动时打印环境变量校验结果，失败会直接退出并提示缺哪个变量
pnpm exec nx serve server
```

前端构建产物里没有运行时配置项 —— admin 是纯静态 SPA，所有环境相关配置（端口/代理/CORS）都在 Vite 配置与 nginx 里，构建后不可再注入。
