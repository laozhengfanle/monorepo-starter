# 文件上传与存储

> 本文介绍文件上传与存储体系：可插拔存储驱动（`StorageModule`）、上传流程、大小限制、`UploadFile` 模型，以及如何扩展新的存储后端。核心代码：`apps/server/src/common/storage/`（驱动抽象）、`apps/server/src/modules/upload/`（上传端点）、`apps/server/src/modules/file-manager/`（文件管理）。

## 1. 架构总览

```text
POST /upload（UploadController，需 JWT）
   │  multer memoryStorage（内存读 Buffer）
   ▼
UploadService ──> StorageService（驱动工厂）
                      │ 按 system_config.storage.driver 选择
        ┌─────────────┴──────────────┐
   LocalStorageDriver           OSS / COS / S3（待扩展）
   （默认，写 uploads/ 目录）      （实现 StorageDriver 接口接入）
```

- `StorageModule` 是全局模块，提供 `StorageService`（驱动工厂），`upload` 模块与 `file-manager` 模块直接注入；
- **controller/resolver 不关心底层实现**，只依赖 `StorageDriver` 接口；
- 驱动选择：`system_config` 的 `storage.driver`（`local` / `oss` / `cos` / `s3`），默认 `local`。

## 2. StorageDriver 接口

```ts
// apps/server/src/common/storage/storage-driver.interface.ts
interface StorageUploadInput {
  originalName: string; // 原始文件名（取扩展名用）
  mimeType: string;
  buffer: Buffer;
  folder: string; // 白名单目录：avatars / logos / files 等
}

interface StorageUploadResult {
  storedName: string; // UUID 重命名后的存储名（防冲突、防路径注入）
  url: string; // 公开访问 URL（local: /uploads/{folder}/{storedName}）
  size: number;
}

interface StorageDriver {
  readonly name: string; // 'local' | 'oss' | 'cos' | 's3'
  upload(input: StorageUploadInput): Promise<StorageUploadResult>;
  delete(input: StorageDeleteInput): Promise<void>;
  // ...
}
```

## 3. 上传流程

1. **端点**：`POST /upload`（`UploadController`），`FileInterceptor` + `memoryStorage` 把文件读入内存 Buffer；
2. **大小限制**：单文件 ≤ **10MB**（`MAX_FILE_SIZE`，multer `limits.fileSize` + `MaxFileSizeValidator` 双重校验）；
3. **认证**：`@UseGuards(JwtAuthGuard)`，记录上传者 `accountId` 与 IP/UA；
4. **落盘**：`UploadService.save` → `StorageService` 按配置选驱动 → 驱动执行 UUID 重命名写入；
5. **静态访问**：本地驱动下文件存 `{UPLOAD_DIR}/{folder}/{storedName}`，`app-setup.ts` 中 `app.use('/uploads', express.static(...))` 暴露，URL 形如 `/uploads/files/{storedName}`；
6. **记录元数据**：写入 `UploadFile` 表（存储名、URL、大小、MIME、分类、上传者），供 file-manager 管理。

```bash
# 示例调用
curl -X POST http://localhost:3301/upload \
  -H "Authorization: Bearer <access-token>" \
  -F "file=@./logo.png" \
  -F "folder=logos"
```

**安全要点**：文件夹白名单（`avatars/logos/files`，不接收用户输入）、存储名 UUID v7 不暴露原始名、`resolve` 后校验最终路径仍在 rootDir 内（路径逃逸防护）、本地驱动 100MB 兜底上限。

## 4. UploadFile 模型

`UploadFile` 记录每个文件的元数据：`storedName`、`url`、`size`、`mimeType`、`category`（文件夹）、`uploaderId`、`createdAt`。文件管理模块（`FileManagerModule`，GraphQL，权限前缀 `config:file:*`）提供列表/删除；删除文件会同时清理存储（驱动 `delete`）并写 `FILE_DELETED` 审计。

## 5. 如何扩展存储后端（OSS / COS / S3）

1. 实现 `StorageDriver` 接口，新建 `apps/server/src/common/storage/oss-storage.driver.ts`：

```ts
@Injectable()
export class OssStorageDriver implements StorageDriver {
  readonly name = 'oss';
  async upload(input: StorageUploadInput): Promise<StorageUploadResult> {
    // 调用阿里云 OSS SDK：UUID 文件名 + 上传 + 返回公开/签名 URL
  }
  async delete(input: StorageDeleteInput): Promise<void> {
    /* ... */
  }
}
```

2. 在 `StorageService` 的驱动工厂中注册（按 `system_config.storage.driver` 分发），并注入所需配置（AccessKey、Bucket、Endpoint 等经 `ConfigService`）；
3. 测试：先切 `storage.driver` 配置到新驱动验证上传/删除/URL 拼接，再补单测（桩掉 SDK）；
4. 注意：云存储的 `url` 为公网地址，`app-setup` 的 `/uploads` 静态目录仅本地驱动需要。

## 6. 注意事项

- **内存上限**：当前用 `memoryStorage`（整文件进内存），10MB 限制下可接受；若放开上限，应改用 `diskStorage` 或流式分片；
- **清理孤儿文件**：上传后业务未落 `UploadFile` 或业务记录被删，会产生孤儿文件；可扩展定时任务扫描（见《定时任务.md》）；
- **指标**：上传成功可 `incFileUpload(category)` 上报 `file_uploads_total`（见《监控与日志.md》）；
- **审计**：上传/删除写 `FILE_UPLOADED` / `FILE_DELETED` 审计（见《审计日志.md》）。

## 7. UPLOAD_DIR 与启动目录（踩坑记录）

- **默认值相对进程 cwd**：`UPLOAD_DIR` 未设置时，本地驱动与静态服务都用 `path.resolve(cwd, 'uploads')`。
- **坑**：`nx run server:serve` 的 cwd 是**仓库根**，默认会指向根 `uploads/`（空目录），而文件实际存于 `apps/server/uploads/` → `/uploads/...` 全部 404。
- **规避**：**始终显式配置 `UPLOAD_DIR`**——
  - 本地 dev：`apps/server/.env` 设 `UPLOAD_DIR=apps/server/uploads`（相对仓库根）；
  - 生产：compose/k8s 设 `UPLOAD_DIR=/app/uploads`（与挂载卷一致）。
