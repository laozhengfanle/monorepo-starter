# 扩展指南

> 本文介绍如何基于现有脚手架新增业务模块：后端（module + service + GraphQL resolver + zod 契约）→ 前端（features 页面 + 权限点 + 菜单）→ 测试，以及共享包下沉原则与 Nx 模块边界规则。建议先读《目录结构.md》与《技术架构.md》。

## 1. 新增业务模块总览

```text
packages/shared/contracts  ── 契约先行：zod schema + 类型（前后端单一事实来源）
        │
apps/server/src/modules/xxx ── 后端：module + service + GraphQL resolver（+ 少量 REST）
        │
apps/admin/src/features/xxx ── 前端：页面 + TanStack Query hooks + antd UI
        │
admin_menu 权限点 + 菜单      ── 权限接入（见《权限控制.md》）
        │
测试：*.spec.ts + e2e          ── 见《测试策略.md》
```

## 2. 后端

1. **契约先行**：在 `packages/shared/contracts/src/lib/schemas/` 新建 `xxx.ts`，定义 zod schema 与导出类型（envelope/分页参考 `common.ts`、`pagination.ts`），在 `src/index.ts` 导出：

```ts
// packages/shared/contracts/src/lib/schemas/order.ts
import { z } from 'zod';
export const OrderListQuerySchema = z.object({ page: z.number().int().min(1).default(1), pageSize: z.number().int().min(1).max(100).default(10) });
export type OrderListQuery = z.infer<typeof OrderListQuerySchema>;
```

2. **创建模块**：`apps/server/src/modules/order/`，包含 `order.module.ts`、`order.service.ts`、`order.resolver.ts`（Code-First GraphQL）：

```ts
// order.resolver.ts（示例骨架）
@Resolver(() => Order)
export class OrderResolver {
  constructor(private readonly orders: OrderService) {}
  @Query(() => [Order])
  @UseGuards(JwtAuthGuard, PermissionGuard)
  @RequirePermission('order:order:list')
  async orders(@Args('query') query: OrderListQuery) {
    return this.orders.list(query);
  }
}
```

3. 契约在 resolver 入参/返回类型中使用（`@Args` 或 DTO），输入校验由全局 `ZodValidationPipe` 承担；
4. 数据访问走 `PrismaService`（注意软删除/分页约定，见《数据库设计.md》）；涉及缓存的用 `CACHE_SERVICE_TOKEN`（见《缓存设计.md》）；变更类操作写审计（见《审计日志.md》）；
5. 在 `AppModule` 的 `imports` 注册新模块。

## 3. 前端

1. `apps/admin/src/features/order/` 建页面（参考 `account` 等既有 feature 的目录约定：页面组件 + TanStack Query hooks + antd 表格/表单）；
2. 数据请求用 `@starter/api-client` 生成的 client / hooks（**应用层禁止直接 import `@starter/contracts`**，见第 5 节边界规则）；GraphQL 侧按既有 resolver 模式写查询；
3. **权限点**：后端 `@RequirePermission` 声明的权限码，前端用 `me()` 权限集合控制菜单/按钮显隐（见《权限控制.md》）；
4. **菜单**：在 `admin_menu` 注册菜单/按钮（`code` 与后端权限码一致），角色勾选后即可在前端看到（`me()` 全量返回由 super_admin 角色保证）；
5. antd 注意 v6 破坏性变更（`App.useApp()` 取 message/notification、`Space.orientation`、`Button color/variant` 等，见仓库 antd 规则）。

## 4. 测试

- 后端：`order.service.spec.ts`（Test.createTestingModule + Prisma 桩）、resolver/guard 分支测试，覆盖率 ≥ 80%；
- 契约：schema 单测（合法/非法输入 parse）；
- e2e：核心闭环补充到 `apps/admin-e2e`；
- 本地验证：`pnpm lint`、`pnpm lint:boundaries`、`pnpm typecheck`、`pnpm test`、`pnpm build`。

## 5. 共享包下沉原则

- **两个及以上应用/包复用才下沉**：一段代码只被 `server` 一个应用使用 → 留在 `apps/server`；被 2 个以上使用（如 server + admin，或未来 member 应用）→ 下沉到 `packages/shared/`；
- 下沉对象：zod 契约（`contracts`）、服务端基建（`server-core`）、UI 组件（`ui`）、测试工具（`test-utils`）；
- 契约是跨前后端的唯一事实来源，**优先下沉**：新模块的入参/出参类型从第一天就放 `contracts`，避免后期复制粘贴导致漂移；
- 下沉时同步更新引用方 import 与边界 lint（`pnpm lint:boundaries` 会拦截违规依赖）。

## 6. Nx 模块边界规则

`eslint.config.mjs` 的 `@nx/enforce-module-boundaries` 是硬约束（CI 的 `pnpm lint:boundaries` 执行）：

| 源 tag         | 允许依赖                                                     |
| -------------- | ------------------------------------------------------------ |
| `scope:shared` | 仅 `scope:shared`（禁止反向依赖应用）                        |
| `scope:admin`  | `scope:admin` + `scope:shared`                               |
| `scope:server` | `scope:server` + `scope:shared`                              |
| `scope:member` | `scope:member` + `scope:shared`（预留，创建 C 端应用时生效） |

附加规则：`apps/admin/**` **禁止直接 import `@starter/contracts`**（`no-restricted-imports`），必须经 `@starter/api-client` 消费契约——保证前端只通过生成 client 访问后端契约。新包创建时给 package.json 打对 tag，跨层依赖会在 lint 时报错。
