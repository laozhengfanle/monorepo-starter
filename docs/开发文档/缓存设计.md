# 缓存设计

> 本文介绍缓存层的抽象与使用：`CacheService`（Redis 优先、内存降级）、cache-aside 模式、缓存管理端点与 key 命名规范。核心代码：`apps/server/src/common/cache/`（接口与实现）、`apps/server/src/modules/cache-admin/`（运维端点）。

## 1. 架构总览

```text
业务代码 ──> @Inject(CACHE_SERVICE_TOKEN) ICacheService
                    │
        ┌───────────┴───────────┐
   Redis 后端（ioredis）   MemoryCacheBackend（无 Redis 时自动降级）
```

- 通过 **`CACHE_SERVICE_TOKEN`（Symbol）** 注入 `ICacheService` 接口，业务代码不依赖具体后端；
- **Redis 优先**：配置了 `REDIS_URL` 等连接时使用 Redis；连接不可用时自动降级为进程内 `MemoryCacheBackend`（Map + 过期时间），开发环境零依赖可跑；
- 接口与实现解耦，测试可注入内存实现或直接桩掉。

## 2. ICacheService 接口

```ts
interface ICacheService {
  get<T>(key: string): Promise<T | null>;
  set(key: string, value: unknown, ttl?: number): Promise<void>; // ttl 秒
  setex(key: string, ttl: number, value: unknown): Promise<void>;
  del(key: string): Promise<void>;
  delByPattern(pattern: string): Promise<void>; // 按通配符批量删，如 'sys:config:*'
  incr(key: string, ttl: number): Promise<number>; // 计数器 +1，首次设置 TTL 防永久键
  exists(key: string): Promise<boolean>;
  // 运维：缓存管理端点使用
  scanKeys(pattern: string): Promise<string[]>; // SCAN 游标，禁用 KEYS *
  getKeyType(key: string): Promise<string>; // Redis TYPE；内存模式恒为 string
  ttl(key: string): Promise<number>; // -1 永不过期 / -2 不存在
  getStats(): Promise<CacheStatsInfo>; // Redis INFO；内存模式降级 '-'
}
```

## 3. cache-aside 模式（读回填 + 写失效）

以系统配置为例（`system-config.service.ts`）：

```ts
const KEY = `${SYSTEM_CONFIG_CACHE_PREFIX}${key}`; // sys:config:{key}
// 读：先查缓存，miss 回填 DB，TTL 30 分钟
let value = await this.cache.get<T>(KEY);
if (!value) {
  value = await this.prisma.client.systemConfig.findUnique(...);
  await this.cache.set(KEY, value, CONFIG_CACHE_TTL); // 1800s
}
// 写：更新 DB 后主动失效缓存
await this.prisma.client.systemConfig.update(...);
await this.cache.del(KEY);
```

关键点：

- **读回填**：`sys:config:` 前缀 + 30 分钟 TTL（`CONFIG_CACHE_TTL = 1800`）；
- **写失效**：配置更新/删除时 `del` 对应 key，而不是直接写缓存（避免写库与写缓存不一致）；
- 批量更新（如 `delByPattern('sys:config:*')`）用于整体失效场景。

## 4. key 命名规范

统一格式：`{域}:{实体}:{标识}`，冒号分层，便于 `scanKeys`/`delByPattern` 按前缀管理：

| 域          | 示例 key                                      | TTL   | 用途                        |
| ----------- | --------------------------------------------- | ----- | --------------------------- |
| `auth`      | `auth:lock:{accountId}` / `auth:lock:ip:{ip}` | 15min | 登录失败锁定计数            |
| `auth`      | `auth:refresh:{accountId}:{hash}`             | 7 天  | refresh token 留存/重用检测 |
| `sys`       | `sys:config:{key}`                            | 30min | 系统配置缓存（cache-aside） |
| `turnstile` | `turnstile:used:{token}`                      | 5min  | 人机验证防重放              |

规范：全小写、冒号分隔、禁止以 `*` 结尾作为正式 key（那是 pattern）；所有带 TTL 的计数器必须用 `incr(key, ttl)`，防止永久键。

## 5. 缓存管理端点（CacheAdminModule）

`CacheAdminModule` 提供 GraphQL 运维接口（权限前缀 `config:cache:*`），全部基于 `scanKeys`（SCAN 而非 KEYS *），并做 pattern 安全校验（拒纯通配符）：

| 操作                      | 说明                                                             |
| ------------------------- | ---------------------------------------------------------------- |
| `listKeys(query)`         | 按 pattern 分页列出 key（含 type/ttl/value/size），`limit ≤ 500` |
| `getValue(key)`           | 单个 key 完整信息（type + ttl + 值）                             |
| `delete / deleteKeys`     | 删除单个 / 批量（≤ 1000）                                        |
| `clearByPattern(pattern)` | 按模式清空（对应 `delByPattern`）                                |
| `getStats()`              | 缓存运行统计（usedMemory / hitRate / uptime）                    |

输入校验由 `@starter/contracts` 的 zod schema（`CacheListQuerySchema` 等）统一承担，非法输入在进服务前被拒绝。

## 6. 使用场景与注意事项

适用场景：

- 读多写少、可接受短暂不一致的数据（系统配置、字典、统计）；
- 计数器类（登录锁定、限流）用 `incr` + TTL 自动过期；
- 认证相关状态（token 黑名单、refresh 留存）见《认证与安全.md》。

注意事项：

- **TTL 必须显式**：除明确的永久值外，一律带 TTL，防止缓存膨胀；
- **不缓存易变数据**：权限聚合当前刻意不缓存（保证变更即时生效，见《权限控制.md》）；
- **序列化**：`set` 的值会被序列化存储，`get<T>` 时保证类型一致；
- **指标**：缓存命中率通过 `BusinessMetrics.setCacheHitRatio(keyPrefix, ratio)` 上报（见《监控与日志.md》）；
- 内存降级模式下 `scanKeys` 为 Map 遍历 + 正则匹配，key 数量大时注意性能。
