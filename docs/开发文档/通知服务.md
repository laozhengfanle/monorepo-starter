# 通知服务

> 本文介绍短信/邮件的可插拔通知体系：`NotificationService` 统一出口、`SmsProvider`/`EmailProvider` 抽象接口、默认 Mock 实现、环境变量选择，以及如何接入真实服务商。核心代码：`apps/server/src/common/notifications/`。

## 1. 架构总览

```text
业务代码 ──> NotificationService（统一出口）
                  │
        ┌─────────┴─────────┐
   sendSms()            sendEmail()
        │                    │
   SMS_PROVIDER_TOKEN    EMAIL_PROVIDER_TOKEN
   （Provider 数组）      （Provider 数组）
        │                    │
   MockSmsProvider      MockEmailProvider
   （默认，仅打日志）     （默认，仅打日志）
```

设计动机：

- 业务层**只依赖 `NotificationService`**，不感知具体服务商（阿里云/腾讯云/nodemailer/SendGrid）；
- Provider 以**数组形式**通过 `useFactory` 注入（`SMS_PROVIDER_TOKEN` / `EMAIL_PROVIDER_TOKEN` 两个 Symbol token），`NotificationService` 运行时按配置选择实现（默认取第一个）；
- 默认注册 Mock Provider：仅打日志、不真实发送，开发环境零配置可跑。

## 2. Provider 抽象接口

`SmsProvider`（`sms.provider.ts`）：

```ts
export interface SmsProvider {
  readonly name: string; // 配置选择标识，如 'mock' | 'aliyun' | 'tencent'
  send(phone: string, templateCode: string, params: Record<string, string>): Promise<void>;
}
```

`EmailProvider`（`email.provider.ts`）：

```ts
export interface EmailProvider {
  readonly name: string; // 如 'mock' | 'smtp' | 'ses'
  send(to: string, subject: string, html: string, text?: string): Promise<void>;
}
```

- `name` 用于配置选择与日志标识；
- `send` 的具体签名/鉴权/模板渲染由各 Provider 自行实现。

## 3. NotificationService 用法

```ts
import { NotificationService } from '../common/notifications/notification.service.js';

@Injectable()
export class SomeService {
  constructor(private readonly notifications: NotificationService) {}

  async sendVerifyCode(phone: string, code: string): Promise<void> {
    await this.notifications.sendSms(phone, 'SMS_VERIFY_CODE', { code }); // 模板变量
  }

  async sendWelcomeEmail(email: string, name: string): Promise<void> {
    await this.notifications.sendEmail(email, '欢迎注册', `<p>你好 ${name}，欢迎！</p>`);
  }
}
```

选择逻辑：`config.get('NOTIFY_SMS_PROVIDER', 'mock')` → 在 Provider 数组中按 `name` 匹配，未命中回退第一个；数组为空时仅 `logger.warn` 并跳过（fail-safe，不抛错）。

## 4. 环境变量选择

| 环境变量                | 取值示例                      | 默认   | 说明               |
| ----------------------- | ----------------------------- | ------ | ------------------ |
| `NOTIFY_SMS_PROVIDER`   | `mock` / `aliyun` / `tencent` | `mock` | 短信 Provider 选择 |
| `NOTIFY_EMAIL_PROVIDER` | `mock` / `smtp` / `ses`       | `mock` | 邮件 Provider 选择 |

生产环境务必显式配置，避免误发到 Mock（Mock 只打日志不真实发送，误配不会产生实际外发，但会"静默丢失"通知，需注意告警）。

## 5. 接入真实服务商

以**阿里云短信**与 **nodemailer（SMTP）** 为例：

1. 实现接口，新建 `providers/aliyun-sms.provider.ts`：

```ts
import { SmsProvider } from '../sms.provider.js';

export class AliyunSmsProvider implements SmsProvider {
  readonly name = 'aliyun';
  async send(phone: string, templateCode: string, params: Record<string, string>): Promise<void> {
    // 调用阿里云短信 SDK（签名、模板变量、Region 等从 ConfigService 读取）
  }
}
```

2. 邮件同理，新建 `providers/smtp-email.provider.ts`（nodemailer + SMTP 配置）；
3. **在 `notifications.module.ts` 注册**（保持多 Provider 数组注入）：

```ts
{
  provide: SMS_PROVIDER_TOKEN,
  useFactory: (): SmsProvider[] => [new MockSmsProvider(), new AliyunSmsProvider()],
},
{
  provide: EMAIL_PROVIDER_TOKEN,
  useFactory: (): EmailProvider[] => [new MockEmailProvider(), new SmtpEmailProvider()],
},
```

4. 配置环境变量切换：`NOTIFY_SMS_PROVIDER=aliyun`、`NOTIFY_EMAIL_PROVIDER=smtp`；
5. 补单测（`notification.service.spec.ts` 模式：注入桩 Provider，断言按 name 分发正确）。

## 6. 注意事项

- **密钥安全**：AccessKey/SMTP 密码经 `ConfigService`（环境变量）注入，禁止硬编码进 Provider；
- **失败语义**：Provider 的 `send` 失败会向上抛，业务调用方自行决定重试/降级（当前服务不做自动重试）；
- **审计**：涉及安全通知（验证码）的发送建议写审计；发送量可埋点到 `BusinessMetrics`（新增自定义指标，见《监控与日志.md》）；
- **模板先行**：真实服务商要求模板审核，开发联调先用 Mock，模板通过后再切真实 Provider。
