# 目录结构

> 完整目录树 + 每个目录/包的职责说明。新成员第一份要读的"地图"。

## 1. 完整目录树

```text
monorepo-starter/
├── apps/
│   ├── server/                     # NestJS 后端（@starter/server，端口 3301）
│   │   ├── src/
│   │   │   ├── main.ts             # 入口（仅构建产物执行；测试用 app-setup）
│   │   │   ├── app-setup.ts        # createApp()：装配 helmet/compression/CORS/Swagger/全局管道过滤器
│   │   │   ├── app/
│   │   │   │   ├── app.module.ts   # 根模块（注册全部 common + modules）
│   │   │   │   └── api.e2e.spec.ts # API 级集成测试
│   │   │   ├── common/             # 与业务无关的横切基建
│   │   │   │   ├── cache/          # CacheService（Redis/内存双后端）+ ICacheService + 模块
│   │   │   │   ├── dataloader/     # DataLoader 工厂（GraphQL 每请求实例）
│   │   │   │   ├── graphql/        # Code-First GraphQL 模块（schema.gql 自动生成 + 错误映射 + 自定义 Scalar）
│   │   │   │   ├── logger/         # nestjs-pino 结构化日志模块
│   │   │   │   ├── metrics/        # Prometheus 模块 + BusinessMetrics 业务指标
│   │   │   │   ├── notifications/  # 通知服务（SMS/Email Provider 抽象 + mock 实现）
│   │   │   │   ├── prisma/         # PrismaService（driver adapter）
│   │   │   │   ├── storage/        # 存储服务（驱动工厂：local 默认，预留 oss/cos/s3）
│   │   │   │   ├── tasks/          # 定时任务（CleanupTask）
│   │   │   │   └── throttler/      # GraphQL 兼容限流守卫
│   │   │   ├── config/             # env 校验（zod）
│   │   │   ├── health/             # Terminus 健康检查
│   │   │   ├── generated/          # prisma-client 生成物（勿手改）
│   │   │   └── modules/            # 业务模块（feature-first，见下）
│   │   ├── prisma/
│   │   │   ├── schema.prisma       # 15 个模型 + erd generator
│   │   │   ├── migrations/         # 迁移历史
│   │   │   └── seed.ts             # 种子数据
│   │   ├── graphql/schema.gql      # Code-First 自动生成的 schema（生成物，勿手改）
│   │   └── .env.example            # 环境变量样例
│   ├── admin/                      # React SPA 管理端（@starter/admin，端口 3302）
│   │   └── src/
│   │       ├── app/                # 应用壳：路由注册表、布局、Provider（Query/Apollo/antd）、auth hooks
│   │       ├── features/           # 业务域页面（feature-first，每域一个目录）
│   │       ├── shared/             # 应用内共享组件/工具（仅本应用使用）
│   │       ├── generated/          # 类型化客户端生成物
│   │       └── assets/
│   ├── admin-e2e/                  # Playwright 端到端测试（@starter/admin-e2e）
│   │   ├── src/smoke.spec.ts       # 冒烟用例
│   │   └── playwright.config.ts
├── packages/
│   └── shared/
│       ├── contracts/              # zod 契约：envelope、分页、DTO schema（前后端单一事实来源）
│       ├── server-core/            # 后端基建：BizException、AllExceptionsFilter、Swagger 装配、zod-args pipe
│       ├── api-client/             # orval 生成的类型化 REST client（React Query hooks + axios mutator）
│       ├── ui/                     # admin 共享 UI 组件（antd 封装、主题 token）
│       └── test-utils/             # 共享测试工具（renderWithRouter 等）
├── docs/                           # 规划与规范文档（本目录为开发文档）
├── openapi/openapi.json            # OpenAPI 产物（server:generate-openapi 发射，orval 输入）
├── scripts/bump-version.mjs        # 版本号升级脚本
├── k8s/ docker-compose*.yml        # 部署编排
└── .github/workflows/              # ci / docs / release / deploy
```

## 2. server 业务模块（modules/）

每个模块 = 一个业务域，文件按职责拆分：

```text
modules/
├── auth/           认证：登录/登出/刷新/me、JWT 守卫、权限守卫、登录锁定、token 黑名单、审计服务
├── admin-account/  管理账户（档案、启用禁用、角色分配、权限覆盖）
├── admin-role/     管理角色 CRUD + 权限点配置
├── admin-menu/     菜单/权限点管理（菜单树构建）
├── audit-log/      审计日志查询（GraphQL resolver）
├── cache-admin/    缓存运维（list/get/delete/clear/stats）
├── dashboard/      仪表盘统计
├── file-manager/   文件管理（上传文件列表/删除）
├── system-config/  系统配置（key-value JSON）
├── system-dict/    数据字典（类型 + 项）
├── turnstile/      Cloudflare Turnstile 人机验证
├── upload/         REST 上传端点（multer → 存储驱动 → UploadFile 表）
└── ws/             WebSocket 网关（socket.io，JWT 握手校验）
```

## 4. 各目录/包职责速查

| 路径                           | 职责                                    | 关键约定                                         |
| ------------------------------ | --------------------------------------- | ------------------------------------------------ |
| `apps/server/src/common/`      | 横切基建，**不依赖任何业务模块**        | 按能力建目录，各有 interface/module/service      |
| `apps/server/src/modules/`     | 业务模块，可依赖 common 与 `@starter/*` | 每模块自含 module/service/resolver/controller    |
| `apps/server/prisma/`          | 数据模型与迁移                          | 表名 snake_case，`@@map` 映射                    |
| `apps/admin/src/features/`     | 业务页面，feature-first                 | 一域一目录，页面在 `pages/` 下                   |
| `apps/admin/src/shared/`       | 应用内共享                              | 仅 1 个应用使用时留在这里                        |
| `packages/shared/contracts/`   | 前后端契约（zod schema）                | 后端校验输入、前端获得类型，**单一事实来源**     |
| `packages/shared/server-core/` | 后端公共基建                            | 不依赖 NestJS 之外的业务代码                     |
| `packages/shared/api-client/`  | 生成的 REST client                      | 手改会被 `pnpm generate:api` 覆盖，改 orval 配置 |
| `packages/shared/ui/`          | 管理端 UI 组件                          | 2+ 应用复用时必须下沉到这里                      |

## 5. 模块边界（机器强制）

所有项目打 `scope:` tag（见各项目 `package.json` 的 `nx` 字段）：

```text
scope:server → 只能依赖 scope:server + scope:shared
scope:admin  → 只能依赖 scope:admin + scope:shared
scope:shared → 只能依赖 scope:shared
scope:member → 预留（C 端）
```

由 `eslint.config.mjs` 的 `@nx/enforce-module-boundaries` 强制执行（`pnpm lint:boundaries`），反向依赖（如 admin → server、shared → admin）会直接报错。

## 6. 复用下沉规则

| 使用范围        | 位置                                      |
| --------------- | ----------------------------------------- |
| 仅 1 个应用使用 | 留在应用内 `features/` 或应用内 `shared/` |
| 2 个应用使用    | 下沉 `packages/shared/`                   |
| 所有应用使用    | 必须 `packages/shared/`                   |

判断标准：先本地写，出现第二处复用时再下沉，不要提前抽象。
