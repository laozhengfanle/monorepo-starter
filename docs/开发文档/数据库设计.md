# 数据库设计

> 本文介绍数据层的总体设计：Prisma 7 模型概览、UUIDv7 主键与软删除约定、ERD 生成方法、迁移工作流。Schema 单一事实源：`apps/server/prisma/schema.prisma`。

## 1. Prisma 7 与 Schema 位置

- ORM：**Prisma 7** + PostgreSQL，driver adapter（`@prisma/adapter-pg`）；
- 客户端生成到 `apps/server/src/generated/prisma-client`（`prisma-client` generator，非 `prisma-client-js`）；
- 业务代码通过 `PrismaService` 访问 `this.prisma.client`（封装了扩展与日志）。

## 2. 模型概览（15 个模型）

| 模型               | 归属域   | 说明                                                                    |
| ------------------ | -------- | ----------------------------------------------------------------------- |
| `Account`          | 用户体系 | 统一身份容器（不存密码/登录标识），含 `tokenVersion`、`enabled`、软删除 |
| `AccountIdentity`  | 用户体系 | 多登录标识（用户名/手机/邮箱 + 凭据哈希）                               |
| `AdminProfile`     | 用户体系 | 管理端档案（昵称、手机、邮箱、头像），软删除                            |
| `AdminRole`        | RBAC     | 角色，`code`（含 `super_admin`）                                        |
| `AdminMenu`        | RBAC     | 菜单/权限点，`code` 即 permissionCode                                   |
| `AdminRoleMenu`    | RBAC     | 角色-菜单关联                                                           |
| `AdminAccountRole` | RBAC     | 账户-角色关联                                                           |
| `AdminAccountMenu` | RBAC     | 账户级权限覆盖（grant/deny）                                            |
| `TokenRevocation`  | 安全     | token 撤销记录（jti 黑名单，含 `'*'` 通配）                             |
| `AuditLog`         | 审计     | 审计日志（action/resourceType 来自词表）                                |
| `UploadFile`       | 文件     | 上传文件元数据（存储名、URL、大小、分类）                               |

| `SystemConfig`     | 系统     | 系统配置（settings / turnstile.config 等 JSON）                         |
| `User`             | 用户体系 | C 端用户（阶段 3 预留），软删除                                         |

## 3. 通用设计约定

**UUIDv7 主键**：所有模型 `id String @id @db.Uuid`。通过 `autoIdExtension`（`apps/server/src/common/prisma/prisma-extensions.ts`）在 `create/createMany` 时自动注入 `newId()`（`@starter/server-core` 导出，基于 `uuidv7`），**业务代码不手写 id**。UUIDv7 时间有序，索引友好，避免自增 id 暴露业务量。

**软删除**：`User / Account / AdminProfile` 有 `deletedAt` 字段。`softDeleteExtension` 自动行为：

- `findUnique / findFirst / findMany` 自动过滤 `deletedAt IS NULL`；
- `delete → update deletedAt`、`deleteMany → updateMany deletedAt`（软删）；
- 其余模型（如 `AuditLog`、`TokenRevocation`）无 `deletedAt`，走物理删除。

**时间戳约定**：`createdAt` 默认 `now()`；变更类模型带 `updatedAt`；`@db.Timestamptz`。**布尔约定**：`enabled` 默认 `true`。

## 4. ERD 生成

```bash
pnpm erd:generate   # → 生成 docs/erd.md（mermaid 格式，无需 puppeteer）
```

- 由 schema 中的 `generator erd`（`prisma-erd-generator`）输出到 `docs/erd.md`；
- 常规构建通过 `DISABLE_ERD=true` 跳过（见 server 的 `prisma-generate` target），不影响 `pnpm build`；
- CI 的 docs workflow 也会在文档发布时重新生成（见《CI-CD.md》）。

## 5. 迁移工作流

```bash
# 开发：修改 schema.prisma 后，生成并应用迁移（dev 环境）
pnpm db:migrate            # prisma migrate dev，会提示迁移名称
# 生产/CI：应用已提交的迁移（只执行，不生成）
pnpm db:deploy             # prisma migrate deploy
# 检查漂移（开发常用，等价于迁移检查）
cd apps/server && pnpm exec prisma migrate status
# 造数据：字典（audit_action/audit_resource 等）由 seed.ts 生成
pnpm db:seed
# 可视化浏览
pnpm db:studio
```

约定：

1. 迁移文件随代码提交（`apps/server/prisma/migrations/`），CI/release 用 `db:deploy` 应用；
2. `db:migrate` 只用于本地开发；不要在多个环境同时 `migrate dev`；
3. 每次改 schema 后必须重新生成客户端（`pnpm exec nx run server:prisma-generate`），CI 的 typecheck/build 依赖生成产物；
4. 删除列/表等破坏性变更需评估软删除与历史数据，先走迁移审查再合入。

## 6. 数据访问注意事项

- 一律通过 `PrismaService` 注入，禁止直接 new PrismaClient（连接池/扩展统一管理）；
- 查询记得带分页（`@starter/contracts` 的 `pagination.ts` 提供统一分页契约）；
- 软删除模型在写 `updateMany`/聚合查询时要留意扩展的自动过滤行为，必要时显式 `deletedAt: null` 条件；
- 大表（如 `AuditLog`）注意索引与清理策略（见《定时任务.md》）。
