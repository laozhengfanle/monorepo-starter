# 监控与日志

> 本文介绍可观测性体系：nestjs-pino 结构化日志（requestId 串联）、Prometheus `/metrics` 端点、业务指标清单与新增指标的方法。核心代码：`apps/server/src/common/logger/`、`apps/server/src/common/metrics/`。

## 1. 结构化日志（nestjs-pino）

日志由 `LoggerModule`（nestjs-pino）统一接管，`createApp()` 中 `bufferLogs + useLogger` 启用：

- 日志以 **JSON 行**输出（pino 格式），每条日志自动带时间戳、级别、模块名；
- **requestId 串联**：一次请求的日志共享同一 requestId，跨服务排障时可沿 requestId 聚合；
- 级别由 `LOG_LEVEL` 环境变量控制（默认 info），开发调试可 `LOG_LEVEL=debug`；
- 业务代码使用 Nest 标准 `Logger` 即可（自动接入 pino），不要 console.log：

```ts
import { Logger } from '@nestjs/common';

@Injectable()
export class SomeService {
  private readonly logger = new Logger(SomeService.name);
  doSomething() {
    this.logger.log('处理开始', { orderId }); // 附加结构化字段
  }
}
```

## 2. Prometheus 端点

`MetricsModule`（`@willsoto/nestjs-prometheus` + prom-client）在应用启动后暴露 **`GET /metrics`**：

```bash
curl http://localhost:3301/metrics
```

- 默认注册表（defaultRegistry）聚合 Node.js 运行时指标 + 自定义业务指标；
- Grafana / Prometheus 直接抓取该端点即可；接入告警按指标名 + label 配置；
- 指标在 `BusinessMetrics`（`business.metrics.ts`）中统一定义，见下节。

## 3. BusinessMetrics 指标清单

`BusinessMetrics` 是事件触发型业务指标 Collector：只定义结构 + 提供语义化方法，埋点由调用方在事件发生时调用。当前清单：

| 指标                       | 类型    | Label          | 埋点方法               | 触发点                                 |
| -------------------------- | ------- | -------------- | ---------------------- | -------------------------------------- |
| `login_failures_total`     | Counter | `reason`       | `incLoginFailure`      | 登录失败（密码错误/账户不存在/已锁定） |
| `login_lockouts_total`     | Counter | `reason`       | `incLoginLockout`      | 登录锁定触发                           |
| `rate_limit_blocked_total` | Counter | `route,reason` | `incRateLimitBlocked`  | 限流拦截（GqlThrottlerGuard）          |
| `audit_log_writes_total`   | Counter | `action`       | `incAuditLogWrite`     | 审计日志写入                           |
| `file_uploads_total`       | Counter | `category`     | `incFileUpload`        | 文件上传                               |
| `cache_hit_ratio`          | Gauge   | `key_prefix`   | `setCacheHitRatio`     | 缓存命中率（0~1，周期计算 set）        |
| `active_connections_total` | Gauge   | —              | `setActiveConnections` | 活跃 WebSocket 连接数                  |

设计原则：

- **事件触发**：计数器在事件发生时 inc，不做定时采集；Gauge 直接 set 绝对值；
- **低基数 label**：`route` 归一化、`reason` 收敛为枚举，禁止把 userId 等无限值放进 label；
- **测试安全**：`getOrCreateCounter`/`getOrCreateGauge` 按名称复用已注册指标，避免测试多次实例化时重复注册报错。

## 4. 如何新增业务指标

1. 在 `BusinessMetrics` 中声明字段并注册（沿用 `getOrCreateCounter` / `getOrCreateGauge` 模式）：

```ts
// 例：订单创建计数
this.orderCreated = getOrCreateCounter({ name: 'order_created_total', help: '订单创建计数', labelNames: ['channel'] }, registry);
```

2. 提供语义化方法（如 `incOrderCreated(channel: string)`）；
3. 在业务事件处调用埋点（构造注入 `BusinessMetrics`）；
4. 补单测（`business.metrics.spec.ts` 模式：注册 → inc → 断言指标值）；
5. 同步更新本清单表格与 Grafana 面板。

## 5. 日志与指标的关系

- **日志**回答"发生了什么"（详情、上下文、错误栈）——用于排障；
- **指标**回答"发生多少、趋势如何"（计数、比率、连接数）——用于告警；
- 审计（《审计日志.md》）是第三种：面向合规的持久化记录，与可观测性正交；
- 新增功能时三件套一起考虑：结构化日志 + 业务指标 + （如涉及敏感变更）审计。

## 6. 常见排查

- `/metrics` 404：确认 `MetricsModule` 已导入且应用已完成 `app.init()`；
- 指标重复注册报错：不要直接 `new Counter(...)`，用 `getOrCreate*` 模式；
- 日志无 requestId：检查是否绕过 `LoggerModule`（直接 pino 实例）或异步任务（定时任务无请求上下文属正常，见《定时任务.md》）；
- label 基数过高：检查是否把高基数值（userId/订单号）放进了 label。
