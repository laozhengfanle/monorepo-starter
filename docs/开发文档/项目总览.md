# 项目总览

> 面向团队开发者的项目导读。阅读本文后可快速了解：这个项目是什么、用什么技术、能做什么、怎么跑起来。

## 1. 项目定位

**monorepo-starter** 是一个企业级全栈 monorepo 脚手架，目标是用一套代码仓库同时承载**管理端（admin）**与**后端 API（server）**，内置常见的后台系统基建能力（认证、RBAC 权限、审计、限流、缓存、文件上传、监控），让新业务模块可以"开箱即写"。

它不是纯模板：仓库内已包含一组**真实可运行**的演示模块（账户/角色/菜单/字典/文件/审计），新业务可以直接照着既有模块的模式扩展（见《扩展指南.md》）。

## 2. 技术栈

| 层       | 选型                               | 说明                                                                                |
| -------- | ---------------------------------- | ----------------------------------------------------------------------------------- |
| 单仓编排 | Nx 23 + pnpm 11.21                 | `catalogMode: strict`，所有依赖版本在根 `pnpm-workspace.yaml` 的 `catalog` 统一管理 |
| 后端     | NestJS 11 + Express                | **不是 Fastify**；Code-First GraphQL + 少量 REST                                    |
| 前端     | React 19 + Vite 8 + Ant Design 6   | TanStack Query 数据请求 + Tailwind CSS 样式                                         |
| 数据     | Prisma 7 + PostgreSQL              | driver adapter（`@prisma/adapter-pg`）+ UUIDv7 主键 + 分页/软删除扩展               |
| 契约     | zod（`@starter/contracts`）        | 前后端单一事实来源；REST client 由 orval 从 OpenAPI 自动生成                        |
| Lint     | oxlint + ESLint                    | oxlint 管代码规则；ESLint 仅跑 Nx 模块边界规则（`pnpm lint:boundaries`）            |
| 测试     | Vitest 4 + Playwright              | 单元/集成用 Vitest（覆盖率阈值 80%），e2e 用 Playwright（admin-e2e）                |
| 监控     | pino + @willsoto/nestjs-prometheus | 结构化日志 + `/metrics` 指标端点 + 自定义 BusinessMetrics                           |
| 定时任务 | @nestjs/schedule                   | 每日 3 点清理过期审计日志与 token 撤销记录                                          |

## 3. 仓库组成

```text
apps/
  server/        NestJS 后端 API（@starter/server，端口 3301）
  admin/         React SPA 管理端（@starter/admin，端口 3302）
  admin-e2e/     Playwright 端到端测试
packages/
  shared/
    contracts/     zod 契约（envelope / 分页 / DTO schema）——前后端单一事实来源
    server-core/   后端基建（业务异常、全局异常过滤器、Swagger 装配）
    api-client/    orval 生成的类型化 REST client（React Query hooks）
    ui/            admin 共享 UI 组件（antd 封装、主题 token）
    test-utils/    测试工具（renderWithRouter 等）
```

内部包统一使用 `@starter/*` scope + `workspace:*` 协议。

## 4. 核心能力

| 能力      | 实现要点                                                                                                            | 详见                  |
| --------- | ------------------------------------------------------------------------------------------------------------------- | --------------------- |
| 认证      | JWT 双 token（access 15min 默认 + refresh 7d），payload 携带 `tokenVersion` + `jti`；jti 黑名单 + tokenVersion 撤销 | 《认证与安全.md》     |
| 登录锁定  | 账号 5 次/15min + IP 50 次/15min，阈值可后台配置；Turnstile 人机验证                                                | 《认证与安全.md》     |
| RBAC 权限 | 角色 → 菜单权限码（permissionCode），账户级 grant/deny 覆盖，super_admin 绕过                                       | 《权限控制.md》       |
| 审计      | `AuditService` 写入 `audit_log` 表，动作词表单一事实源，fail-open 容错                                              | 《审计日志.md》       |
| 限流      | `@nestjs/throttler` 全局 100 次/分钟，敏感端点单独收紧，GraphQL 兼容守卫                                            | 《认证与安全.md》     |
| 缓存      | `CacheService`：Redis 优先（`REDIS_URL`），未配置自动降级内存；运维端点管理 key                                     | 《缓存设计.md》       |
| 文件上传  | 可插拔存储驱动（默认本地磁盘，预留 OSS/COS/S3），10MB 上限，审计留痕                                                | 《文件上传与存储.md》 |
| 监控      | pino 结构化日志 + Prometheus `/metrics` + 业务指标（登录失败/限流拦截/审计写入/上传/缓存命中率/WS 连接数）          | 《监控与日志.md》     |
| 通知      | `NotificationService`：短信/邮件 Provider 抽象，默认 mock，生产可接阿里云/nodemailer                                | 《通知服务.md》       |
| N+1 优化  | DataLoader 工厂注入 GraphQL context（菜单树/角色码批量查询）                                                        | 《技术架构.md》       |

## 5. 快速开始

```bash
# 环境要求：Node >= 22.18（推荐 24）、pnpm 11
pnpm install

# 准备数据库与 .env（本机 PostgreSQL 或 docker-compose）
cp apps/server/.env.example apps/server/.env   # 按需改 DATABASE_URL
pnpm db:migrate        # prisma migrate dev（含 client 生成）
pnpm db:seed           # 种子数据（含 super_admin 角色、字典、演示账户）

# 开发
pnpm exec nx serve server   # http://localhost:3301（Swagger: /api-docs，GraphQL: /graphql）
pnpm exec nx serve admin    # http://localhost:3302（/api 代理到 3301）

# 常规检查
pnpm build / pnpm test / pnpm lint / pnpm typecheck / pnpm e2e
```

## 6. 常用命令速查

```bash
pnpm lint              # oxlint 代码规则
pnpm lint:boundaries   # ESLint 模块边界规则（Nx enforce-module-boundaries）
pnpm typecheck         # nx run-many -t typecheck
pnpm test              # nx run-many -t test（Vitest）
pnpm e2e               # nx run-many -t e2e（Playwright）
pnpm generate:api      # orval 从 OpenAPI 重新生成 @starter/api-client
pnpm db:migrate        # 开发环境迁移（apps/server 下 prisma migrate dev）
pnpm db:deploy         # 生产环境应用迁移（migrate deploy）
pnpm db:seed           # 种子数据
pnpm db:studio         # Prisma Studio
pnpm erd:generate      # 生成 docs/erd.md（mermaid 格式 ERD）
pnpm bump              # 版本号升级脚本（默认 patch，可 minor/major）
```
