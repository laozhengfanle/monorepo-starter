# 审计日志

> 本文介绍安全审计体系：动作词表的单一事实源、`AuditService.write` 用法、fail-open 容错设计，以及如何新增审计动作。核心代码：`apps/server/src/modules/auth/audit.constants.ts`（词表）、`audit.service.ts`（写入）、`apps/server/src/modules/audit-log/`（查询网关）。

## 1. 动作词表：单一事实源

审计动作（`audit_log.action`）与资源类型（`audit_log.resourceType`）**只允许来自** `audit.constants.ts`：

```ts
import {
  AUDIT_ACTIONS, // 动作枚举：login_success / account_created / role_assigned ...
  AUDIT_RESOURCES, // 资源类型：admin_account / admin_role / auth ...
  AUDIT_ACTION_LABELS, // 动作中文标签（字典生成源）
  AUDIT_RESOURCE_LABELS, // 资源中文标签（字典生成源）
  AUDIT_ACTION_RESOURCE_MAP, // action → 默认 resourceType
} from '../auth/audit.constants.js';
```

概念模型：

- **action = 动词**（做了什么）：`login_success`、`account_created`、`role_assigned`；
- **resourceType = 名词**（作用于哪类实体）：`admin_account`、`admin_role`、`auth`；
- 一对多：一个资源类型聚合多个动作，按资源类型筛选可跨动作查看实体生命周期；
- `AUDIT_ACTION_RESOURCE_MAP`：action → 默认 resourceType，`write` 未显式传时自动补全，杜绝漏填/不对称（如 `login_*` 自动归 `auth`；`DICT_*` 默认归 `sys_dict_type`，写 `sys_dict_item` 时调用方显式覆盖）。

> 该文件是**纯常量、无任何 Nest 依赖**，因此可被 seed / 测试直接引用，保证运行时代码与字典一致。

## 2. AuditService.write 用法

```ts
import { AuditService, AUDIT_ACTIONS } from '../auth/audit.service.js';

@Injectable()
export class SomeService {
  constructor(private readonly audit: AuditService) {}

  async createAccount(...) {
    // ...业务逻辑
    await this.audit.write({
      accountId: operator.accountId,   // 操作者（可选，系统任务可省略）
      action: AUDIT_ACTIONS.ACCOUNT_CREATED, // 必须 ∈ 词表
      // resourceType 可省略：按 AUDIT_ACTION_RESOURCE_MAP 自动补全
      resourceId: newAccount.id,
      detail: { username: newAccount.username }, // 结构化明细，避免拼进文案
      ip: requestIp,
      userAgent: requestUserAgent,
    });
  }
}
```

要点：

- `write` 是**异步且不阻塞主流程**的旁路写入，业务代码 `await` 后无需处理返回值；
- `resourceType` 缺省时自动补全；`DICT_*` 写字典项时显式传 `AUDIT_RESOURCES.SYS_DICT_ITEM`；
- 写入动作同时上报 `audit_log_writes_total{action}` 指标（见《监控与日志.md》）。

## 3. fail-open 容错设计

审计是"记录"而非"判定"，因此整体设计为 **fail-open**：

- `action` 不在词表中：仅 `Logger.error` 告警，**不阻断写入**（保证字典可扩展、老数据可读）；
- `create` 落库失败：仅 `Logger.error`，**不抛出**——审计旁路失败绝不能阻塞/回滚主流程（如登录失败、改密、配置更新等安全敏感路径）；
- 结论：审计只损失"日志本身"，不影响既定安全判定（限流、锁定照常生效）。

## 4. 查询与维护

`AuditLogModule` 提供 GraphQL 数据网关（权限前缀 `config:audit:*`），支持分页、筛选、清空与导出：

| 能力      | 说明                                        |
| --------- | ------------------------------------------- |
| 分页/筛选 | 按操作者、动作、资源类型、时间段过滤        |
| 清空      | 记录 `AUDIT_CLEARED` 审计后清空（高危操作） |
| 导出      | 运维导出 CSV/JSON                           |

数据保留策略：`CleanupTask` 每日 3 点删除 **90 天前**的审计日志（合规保留窗口），见《定时任务.md》。`sys_dict` 中 `audit_action` / `audit_resource` 两个字典由 `audit.constants.ts` 经 seed 生成，保证后台筛选下拉与词表一致。

## 5. 如何新增审计动作（4 步）

1. **加常量**：在 `AUDIT_ACTIONS` 追加，如 `ORDER_EXPORTED: 'order_exported'`；
2. **补标签**：在 `AUDIT_ACTION_LABELS` 加中文标签（后台筛选下拉显示）；
3. **声明默认资源**：在 `AUDIT_ACTION_RESOURCE_MAP` 映射默认 resourceType（如 `ORDER` 资源）；
4. **同步字典**：重跑 seed（`pnpm db:seed`）使 `audit_action` 字典自动同步；若新增了资源类型，同步补 `AUDIT_RESOURCES` 与 `AUDIT_RESOURCE_LABELS`。

完成后跑 `pnpm typecheck` 与 `pnpm test`（`audit.constants.spec.ts` 会校验词表完整性：标签全覆盖、映射全覆盖、动作在字典中）。
